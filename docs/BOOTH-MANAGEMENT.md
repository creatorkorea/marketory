# 부스 자원과 배치

2026-10-09 구현 시작, 2026-10-11 검증·반영. 업무 명세 v1.3 BTH-001–007을 기준으로 한다.

## 운영 흐름

마켓의 ‘부스 배치’에서 부스 번호·구역과 전기·화기·냉장·차량 접근·테이블 수용량을 등록한다. 부스를 사용할 수 없으면 사용 중지로 설정한다. 이미 확정 배치된 부스는 해당 셀러의 조건을 충족하지 못하도록 바꿀 수 없다.

참가확정된 셀러만 배치 대상에 나타난다. 후보마다 조건 충돌과 기존 점유 경고를 확인하고 부스를 선택한다. 조건 기반 후보는 AI 평가가 아니며, 최종 선택은 운영자가 한다. 테이블 수용량 미정은 양수의 테이블 요구를 충족한 것으로 보지 않는다.

‘초안 저장’은 변경할 셀러와 부스의 조합을 저장한다. 현재 확정 배치는 그대로 유지되며, 초안은 자원을 점유하지 않는다. 기존 초안을 다시 저장하면 이전 초안은 폐기 이력으로 남는다. 초안을 비우는 것과 실제 배치를 해제하는 것은 별도 작업이다.

‘배치 확정’은 저장된 변경 집합 전체를 한 번에 적용한다. A01과 A02의 셀러를 서로 바꾸려면 두 셀러의 목표 부스를 함께 지정한다. 변경 집합 밖의 셀러가 점유한 부스를 가져올 수 없으며, 검증이나 저장 중 실패하면 기존 배치 전체를 유지한다. 미배치 셀러가 있어도 일부 배치를 확정할 수 있고 미배치 인원을 표시한다.

## 변경·취소와 권한

- 운영자·플랫폼 관리자: 부스 등록·수정, 초안·확정·해제.
- 검수자: 배정 마켓의 배치 조회. 셀러 연락처·사업자 자료·심사 메모는 이 화면에서 반환하지 않는다.
- 조회자: 기존 마켓 집계만 허용하며 배치 원문 API는 거절한다.
- 셀러: 내 신청에서 본인의 확정 부스 번호·구역·시설만 확인한다. 내부 현장 메모·초안·타인 배치는 공개하지 않는다.

신청 취소 시 활성 배치와 해당 신청의 초안을 같은 트랜잭션에서 해제한다. 해제자·시각·사유를 보존하며, 같은 요청 재시도는 중복 처리하지 않는다. 수동 배치 해제는 신청의 참가확정 상태를 취소하지 않는다. 행사 종료 후 변경은 차단하고, 모집 마감 상태에서도 행사 종료 전에는 배치 업무를 허용한다.

## 구현 계약

API는 `GET/POST /api/projects/{id}/booths`, `PATCH /api/projects/{id}/booths/{booth_id}`, `POST /api/projects/{id}/booth-draft`, `booth-confirm`, `booth-release`다. 변경에는 `Idempotency-Key`, 현재 `project.version`에 해당하는 `expected_version`, 사유를 보낸다. 초안은 신청 버전과 저장 시점 부스 버전을 보존한다. 확정 시 현재 버전·참가 상태·시설·점유를 다시 검사한다.

잠금은 요청 키 → 현재 사용자 → 프로젝트 → 신청 ID 순 → 부스 ID 순 → 배치 순서다. 확정·해제는 관련 신청의 version을 증가시키며 제출 내용 revision은 유지한다. 프로젝트 version은 부스 변경당 한 번 증가한다. 따라서 다른 운영자의 부스·마켓 변경을 확인하기 전에는 오래된 화면으로 덮어쓸 수 없다.

DB 변경은 `20261009083029_booth_management.sql`이다. 부스와 신청의 프로젝트 일치를 복합 FK로 강제하고, 확정 상태이며 미해제인 부스·신청에 각각 고유 인덱스를 둔다. 추천·초안은 점유 인덱스에 포함하지 않는다. 해제 이력은 변경·삭제하지 않는다. 두 테이블은 RLS를 활성화하고 브라우저 역할의 직접 접근 권한을 제거한다.

## 검증과 후속 범위

로컬 격리 DB 테스트는 권한·재조회·버전·조건 충돌·동시 확정·교환 롤백·취소 회수·이력 보존을 검증한다. 브라우저는 고정 API 데이터로 입력·초안과 확정 구분·모바일·키보드·요청 복구를 확인한다. 실제 고객 배치나 외부 발송은 실행하지 않는다.

안내 초안 생성·승인·발송은 P7에서 별도 연결한다. AI 부스 추천, 도면 기반 드래그 편집, XLSX 출력은 현재 화면에 포함하지 않는다. 현재 방식은 조건 후보와 선택 입력으로 운영자가 직접 확정하는 배치다.

Supabase 프로젝트 `xtuznofafxlwlggnolns`에 부스 마이그레이션 한 건을 반영했다. 적용 이력·두 테이블의 RLS·브라우저 역할 직접 권한 0건·활성 배치 고유 인덱스 2개를 재조회했다. 실제 고객 배치를 만들거나 변경하지 않았다.

독립 검토에서 확인한 초안 입력 손실, 취소된 신청의 선택 제거, 다른 운영자가 초안을 바꾼 뒤 부스 수정이 막히는 문제를 수정했다. 모바일 390px와 데스크톱 1440px 캡처는 gitignored `output/booths-mobile.png`, `output/booths-desktop.png`에 저장했다.

2026-10-11 최종 검증: 웹 단위 54개, API 통합 70개, 전체 브라우저 fixture 42개 통과. 생성 타입·타입 검사·Ruff·프로덕션 빌드 통과. 브라우저 보고서는 `output/booths-browser-full.json`에 보관했다. 로컬 API readiness 응답도 정상이다.

## 2026-10-12 공개 배포 검증
