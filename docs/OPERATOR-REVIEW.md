# 운영자 심사와 참가확정

2026-10-09 구현. 기준은 업무 명세 v1.3이며, 배포 완료를 뜻하지 않는다.

## 사용 흐름

마켓 목록의 ‘신청 검토’에서 상태·상품 분류로 신청을 조회한다. 작성 중인 신청은 보이지 않는다. 상세에서 검토 시작, 보완 요청·연장, 선정·대기·탈락, 대기자 선정, 확정기한 연장과 내부 메모를 처리한다. 선정 시 참가확정 기한을 입력하며, 셀러는 내 신청에서 직접 확정한다. 운영자 대리 확정에는 참가 의사 확인 근거가 필요하다.

기한 입력은 KST를 표시한다. 변경은 확인 다이얼로그와 서버 성공 응답 이후 반영한다. 충돌 시 최신 상태를 확인하고 다시 결정한다. 여전히 허용되는 처리 종류와 입력값은 유지한다. 응답 유실은 기존 요청 키·본문으로 결과를 복구하며, 권한 회수 시 상세를 닫는다.

## 권한과 데이터

| 사용자 | 허용 범위 |
|---|---|
| 관리자·배정 운영자 | 신청 상세, 결정, 기한 변경, 메모, 대리 확정 |
| 배정 검수자 | 연락처가 마스킹된 상세, 상품 사진, 프로젝트 내부 메모 |
| 배정 조회자 | 상태별 집계와 정원 |
| 셀러 | 본인 신청과 참가확정·취소; 내부 메모와 대기 순위는 비공개 |

검수자에게 사업자 증빙·원본 snapshot·운영자용 안내 초안을 반환하지 않는다. 저장된 변경 결과를 다시 조회할 때도 현재 권한을 검사한다. 운영자 응답을 저장한 후 검수자로 낮아진 계정에는 해당 응답을 재전달하지 않는다.

## 상태와 동시성

- 접수 → 검토 중 → 선정·대기·탈락. 대기는 선정 또는 탈락으로 처리한다.
- 접수·검토 중에서 보완을 요청한다. 보완·확정기한 연장은 기존 기한보다 늦고 행사 종료보다 이르다.
- 선정·참가확정 합계가 정원이다. 마지막 자리 동시 선정과 프로젝트 정원 축소는 같은 프로젝트 잠금으로 보호한다.
- 마감된 프로젝트에서도 행사 종료 전에는 참가확정과 확정기한 연장이 가능하다. 새 심사 결정은 차단한다.
- 기한 경과는 자동 취소를 만들지 않는다. 확정과 취소가 경합하면 한 변경만 성공한다.
- 상태·메모 변경은 version을 증가시키고 제출 내용 revision을 바꾸지 않는다. 감사 기록과 요청 결과를 같은 트랜잭션에 저장한다.

## 구현 위치

API: `reviews.py`, `review_domain.py`, `confirmation.py`. 화면: `components/reviews`, `components/seller/application.tsx`. 계약: 생성된 OpenAPI와 TypeScript 타입. DB 변경: `20261009081137_operator_review_results.sql`의 역할별 동기 요청 결과 만료 허용과 신청 감사 이력 인덱스.

결정·기한 변경의 안내 내용은 `REVIEW.NOTICE_DRAFT` 감사 기록에 **발송 불가능한 초안 snapshot**으로 남긴다. 통신 테이블, 승인, 발송 요청, worker는 P7에서 연결한다. 현재 화면은 실제 메일 발송이나 AI 평가를 실행하지 않는다.

## 검증 범위와 남은 작업

격리된 로컬 PostgreSQL 통합 테스트와 브라우저 fixture로 권한·마스킹·기한·동시 선정·확정/취소·응답 복구·충돌 입력 보존·모바일을 검증한다. 실제 운영 신청의 결정이나 수신자 발송은 테스트하지 않는다. 실제 사용자 전체 흐름과 배포 후 검증은 별도로 남는다.

후속 범위는 AI 평가 비동기 작업(P5 잔여), 부스 배치(P6), 승인 후 안내 발송(P7), 이메일 snapshot 명시 동기화 및 전체 운영 검증이다.
