한 문장 정의

핵심 가설

행사 운영자는 “신청을 받는 기능”보다 모집-심사-배치-안내까지 연결되는 운영도구에 비용을 지불한다.

셀러 정보와 프로젝트별 신청정보를 분리하면 여러 행사를 동시에 운영하면서 데이터가 축적된다.

AI는 최종 선발자가 아니라 심사 보조자 역할을 할 때 현장 적용성이 높다.

자운대 프로젝트에서 검증한 기능은 다른 축제·야시장·상권행사에 재사용할 수 있다.

## 5  AI Agent 적용 설계

AI의 역할은 “자동 탈락”이 아니라 “운영자 판단 보조”로 한정한다.

<a id="table-11"></a>
**표 11**

| Agent/기능 | 입력 | 출력 | Human-in-the-loop |
| --- | --- | --- | --- |
| Application Agent | 셀러 신청정보 | 핵심정보 요약, 누락 항목 | 누락 보완 요청 여부 |
| Classification Agent | 상품명·설명·사진 설명 | 카테고리 자동 분류 | 운영자 수정 가능 |
| Evaluation Agent | 프로젝트 기준 + 신청정보 | 적합도 점수, 추천이유, 위험사항 | 최종 선정은 운영자 |
| Duplicate Agent | 동일 프로젝트 신청목록 | 유사 업종·상품 군집 | 과다 카테고리 판단 |
| Booth Agent | 부스 조건 + 셀러 요구 | 배치 추천 | 운영자가 최종 배치 |
| Communication Agent | 선정상태·운영정보 | 안내문 초안 | 발송 전 운영자 확인 |

## 6  핵심 데이터 구조

MVP는 다음 6개 데이터 엔티티를 중심으로 설계한다.

<a id="table-14"></a>
**표 14**

| Entity | 핵심 필드 | 설명 |

| Seller | seller_id, user_id, 상호, 대표자, 연락처, 사업자정보 | 인증 계정에 연결된 셀러 마스터 |
| Project | project_id, 행사명, 기간, 장소, 모집정책, 심사기준 | 자운대 등 개별 행사 |

| Evaluation | application_id, version_no, status, summary, AI점수·근거 | AI 실행·평가 이력, 사람 결정은 신청 상태이력에 저장 |
| Booth / BoothAssignment | project_id, booth_no, 조건 / application_id, released_at | 부스 자원과 추천·확정·해제 이력 분리 |
| Communication | application_id, message_type, 내용, 발송일, 상태 | 선정·대기·탈락·행사안내 이력 |

## 9 MVP 범위와 운영 기준 보완

초기 MVP는 단일 운영조직이 여러 프로젝트를 운영하는 서비스로 정의한다. 고객사별 독립 가입·결제·테넌트 격리는 후속 범위다. 여러 고객사를 같은 배포 환경에 수용하기 전에는 조직 모델과 공유 셀러의 정보 이용 범위를 다시 설계한다.

관리자와 셀러는 이메일 OTP 인증을 사용한다. 셀러 1계정당 셀러 마스터 1개를 기본으로 하며 연락처·사업자번호 중복은 운영자 검토용 후보다. 다른 계정의 셀러에 자동 연결하지 않는다. 모집공고는 비로그인 조회를 허용하고 작성·제출·내 신청은 인증 후 사용한다.

## 10 가입과 행사 당일 운영

모집공고는 비로그인 조회를 허용한다. 신규 셀러는 이메일 OTP 인증 후 자동으로 일반 셀러 계정을 생성하고 이름·상호·연락처를 입력한다. 안내 주소는 인증 이메일을 사용하므로 별도 미검증 주소로 발송하지 않는다.

로그인에 사용하는 인증 제공자의 검증 완료 이메일을 안내 주소의 유일한 원본으로 사용한다. 최초 제출 때 applications.notification_email과 notification_email_verified_at으로 복사한다. 계정 이메일 변경은 기존 신청 수신처를 자동 변경하지 않는다. 셀러가 내 신청에서 현재 검증된 계정 이메일로 동기화를 요청한 경우에만 변경하며 임의 주소 입력은 받지 않는다.

업무 변경은 현재시각 < projects.event_end_at이고 프로젝트가 COMPLETED가 아닐 때만 허용한다. 행사 당일에도 이 조건 안에서 참가확정·취소·부스 변경·긴급 안내를 처리한다. 마감 후에는 신규 업무를 만들지 않되 기존 AI/발송 작업 결과 기록, UNKNOWN 결과 확인, 감사로그 추가, 개인정보 보관·삭제 관리 작업은 권한을 검사해 허용한다.

운영자는 보완기한 만료 신청을 연장하거나 취소할 수 있다. 발송 결과가 불명확한 경우에는 확인 근거를 남긴 후 결과를 확정한다. 행사 당일에는 두 셀러의 부스를 한 번에 교환할 수 있고 변경 대상에게 승인된 안내를 발송한다.

## 11 발송 확인과 신청 안정성

운영자가 안내 내용을 승인하면 발송 준비 상태가 된다. 별도 발송 요청을 실행한 경우에만 실제 발송 대기열에 들어간다. 화면은 승인 완료·발송 대기·발송 중·제공사 접수 결과를 구분한다.

요청 결과의 보관기간이 끝나도 동일 요청을 자동 재실행하지 않는다. 화면은 만료를 안내하고 현재 업무 상태를 확인하도록 연결한다.

셀러가 여러 사진을 선택하면 한 장씩 연결을 완료하고 진행 개수와 실패 파일을 표시한다. 네트워크 응답이 끊겨도 동일 작업을 중복 생성하지 않도록 요청 결과를 복구한다. 이 기능의 완료조건은 E2E-36~42와 연결한다.
