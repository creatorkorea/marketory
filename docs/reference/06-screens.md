## 플리마켓 플랫폼 MVP 화면설계서

Version 1.3  |  2026.10.08

셀러의 모집공고 접속부터 신청·보완·결과 확인·참가확정까지, 운영자의 프로젝트 설정부터 심사·부스·안내까지 화면 동선과 동작을 정의한다. 화면 ID는 기능 ID 및 DB/API와 연결한다. 색상·로고·최종 시각 디자인은 별도이며 본 문서는 화면의 정보와 동작 계약이다.

## 2 공통 화면 규칙

모바일 신청은 단일 열 단계형 폼으로 구성하고 각 단계에서 임시저장 상태와 오류 위치를 보여준다. 필수정보가 없는 DRAFT도 저장할 수 있다. 제출 버튼 중복 클릭을 막고 서버 멱등성을 함께 사용한다. 로그인 만료 시 저장된 작성값을 보존하고 인증 후 복귀한다. 공유 기기 브라우저에 민감정보를 영구 저장하지 않는다.

빈 목록, 로딩, 네트워크 실패, 권한 없음, 마감, 동시수정 충돌을 각각 표시한다. 409 시 저장 실패 이유와 최신 데이터 다시 불러오기를 제공하고 기존 입력을 덮어쓰지 않는다. 중요한 취소·일괄 배치·발송은 대상 수와 변경 내용을 확인한 뒤 실행한다. 키보드 탐색·입력 레이블·오류 연결·색상 외 상태 텍스트를 지원한다.

## 3 SCR 01 프로젝트 대시보드

연결 기능 PRJ-001/003, COM-002

상단에 프로젝트 생성, 검색·기간·상태 필터를 둔다. 목록은 행사일·모집상태·신청/심사/선정/대기/확정 건수를 표시한다.

프로젝트 생성은 STAFF 중 PLATFORM_ADMIN 또는 적어도 한 프로젝트의 활성 OPERATOR에게 허용한다. 최초 운영계정·최초 프로젝트는 플랫폼 관리자가 준비한다. 생성 즉시 생성자 OPERATOR 멤버를 저장한다.

집계에서 DRAFT/CANCELLED를 신청수에서 제외한다. APPROVED와 CONFIRMED는 별도 수로 표시하고 모집정원 계산에는 합계를 사용한다.

## 4 SCR 02 프로젝트 설정

연결 기능 PRJ-002/005/006

기본정보·모집정책·심사기준·부스조건·공개상태 탭을 둔다. 사진 필수 여부, 사업자 요건, 카테고리와 동의 문구버전을 입력한다.

저장 전 기간 순서·양수 정원·가중치 합계·필수값을 검증한다. 모집 중 정책 수정은 변경사유와 영향 신청 수를 표시하고 policy_version을 증가시킨다.

종료 버튼은 신규 업무 변경이 차단된다는 점을 안내하고 기존 발송 결과 확인은 계속 가능하다고 설명한다. 실제 행사값과 제공사 비밀키를 화면 기본 예시로 채우지 않는다.

## 5 SCR 03 셀러 신청

연결 기능 SEL-001/002/003, APP-001/002/003/006

①본인 프로필 ②상품·가격·카테고리·사진 ③전기·테이블·화기·냉장·차량 요구 ④동의·최종 확인의 4단계로 구성한다.

최초 OTP 완료 후 bootstrap으로 일반 셀러 계정을 생성하고 이름 입력을 포함한 프로필 단계로 이동한다. 프로필은 인증된 user_id로만 연결한다. 연락처 중복 여부로 타인의 상호·프로필을 노출하지 않는다. 신규 신청 화면에는 기존 프로필 값을 기본값으로 제공한다.

사진 업로드는 한 파일씩 진행하며 전체 개수·현재 파일·연결 완료·실패·다시 시도를 표시한다. 허용 MIME·파일 수·최대 크기는 서버 정책과 동일하게 표시한다. 제출 전 누락은 해당 입력으로 이동하고 DRAFT를 유지한다.

보완 화면은 info_requests_json의 필드·이유·기한을 상단에 보여주며 요청 필드만 수정한다. 모집 마감과 보완기한을 구분한다. 제출 완료 화면은 접수번호·접수시각·내 신청 이동을 제공한다.

## 6 SCR 04와 SCR 05 신청 심사

연결 기능 REV-001~009, AI-001~005

목록은 상호·카테고리·상태·제출시각·AI점수·주의 플래그를 표시한다. 연락처는 상세의 허용 권한에서만 노출한다. 필터 상태는 상세에서 뒤로 이동해도 유지한다.

상세는 신청 당시 원문/snapshot, AI 요약·근거·추천·입력버전, 보완·선정 이력으로 구분한다. AI 실패·이전 revision 결과는 점수 옆에 명시한다.

OPERATOR에게 보완요청·승인·대기·탈락·AI 재실행을 제공한다. 승인은 확정기한, 대기는 순위, 탈락·취소는 사유를 입력한다. REVIEWER는 연락처가 마스킹된 신청·평가·상품사진 조회와 메모만 가능하며 사업자 증빙·출력은 차단한다.

최종결정 전 최신 version과 정원 검사를 수행한다. AI가 없어도 수동 심사를 허용하며 AI 결과가 운영자 결정을 바꾸지 않는다.

## 7 SCR 06 부스 배치

연결 기능 BTH-001~006

확정 셀러 목록과 부스 자원 목록을 나란히 보여주되 좁은 화면에서는 순차 표시한다. 전기·화기·냉장·차량·테이블 조건 필터를 제공한다.

추천 결과는 미확정 표시하며 실제 배정과 구분한다. 최종 확정 버튼은 배치 수·충돌·기존 변경 대상을 보여준 뒤 실행한다.

다른 프로젝트 연결·부스 이중 점유·한 신청의 복수 활성 부스는 차단한다. 변경 시 이전 배치 해제 이력을 남기고 대상자 변경 안내 초안을 준비한다. 취소한 신청은 활성 배치 목록에서 제거한다.

## 8 SCR 07 안내와 운영자료

연결 기능 MSG-001~007, EXP-001~003

대상·채널·유형 → 수신자별 미리보기 → 승인 완료 READY → 명시 발송 요청 QUEUED → 처리 중 SENDING → 결과 순서로 구성한다. 발송 수와 수신처·개인화된 부스·기한을 확인할 수 있어야 한다.

DRAFT/READY/QUEUED/SENDING/SENT/FAILED/UNKNOWN을 표시한다. SENT는 제공사 접수 성공이라는 설명을 제공한다. UNKNOWN은 결과 확인 액션을 우선 제공하고 즉시 재발송 버튼을 비활성화한다.

승인 후 내용이나 대상의 상태·부스가 바뀌면 재승인이 필요하다. 이전 승인·실행 시도·오류·확인 근거를 상세 이력에서 조회한다.

운영자료 탭은 현재 필터·행사명·생성시각을 포함한 XLSX 명단·부스표를 다운로드한다. 연락처 포함 여부와 권한을 검사하고 출력 이력을 기록한다.

## 9 SCR 08 내 신청과 참가확정

연결 기능 APP-004/005, CNF-001/002/004

행사명·접수번호·현재 상태·다음 행동을 맨 위에 표시한다. NEED_INFO는 보완 버튼·항목·info_due_at, APPROVED는 confirm_due_at과 참가확정/취소 버튼을 제공한다.

CONFIRMED는 참가확정 시각과 운영자가 확정한 부스만 표시한다. 추천 단계 부스와 내부 AI평가·심사메모는 공개하지 않는다. WAITING은 대기 상태와 다음 안내 방식을 표시하되 내부 순위를 자동 공개하지 않는다.

확정 링크는 인증 후 이 화면으로 이동하며 로그인 없이 상태를 바꾸는 토큰 링크로 만들지 않는다. 기한 만료는 운영자 문의를 표시하고 자동 취소하지 않는다.

취소는 사유와 되돌릴 수 없음을 확인한 뒤 실행한다. CANCELLED/REJECTED/완료 행사는 새 신청·재확정 버튼을 제공하지 않는다.

## 10 화면 검수 기준

각 화면은 정상·빈 상태·로딩·실패·권한 없음·동시수정 상태를 확인한다. 모바일 360px 이상에서 핵심 신청·사진·동의·확정 흐름을 가로 스크롤 없이 완료한다. 본인/타인 계정과 OPERATOR/REVIEWER/VIEWER를 구분해 E2E-01~44를 실행한다. 화면 검수 통과와 서버 권한·DB 제약 검증 통과를 각각 기록한다.

## 12 화면과 복구 동선

<a id="table-03"></a>
**표 03**

| 상황 | 표시와 동작 |
| --- | --- |
| READY | 승인 완료로 표시하고 별도의 발송 버튼 제공. 승인만으로 발송 중 표시를 하지 않음 |
| QUEUED | 발송 요청 접수·요청자·시각 표시, 같은 요청 중복 클릭 차단. 요청 내용 수정은 서버 철회 성공 확인 후 가능 |
| SENDING | 제공사 호출 중 표시, 철회 성공을 보장하는 버튼 제공 금지. 결과 불명은 UNKNOWN 확인 동선 |
| 요청 응답 유실 | 처리 결과 확인 중 표시, 기존 요청 키를 유지. UNRESOLVED를 실패 완료로 표시하지 않음. 새 키 재실행 유도 금지 |
| 사진 여러 장 | 예: 3/10 연결 완료. 현재 파일의 연결 완료 전 다음 파일의 업로드 URL을 요청하지 않음 |
| 사진과 폼 저장 | 같은 신청의 변경을 순서대로 실행, 미완료·실패 파일이 있으면 제출 버튼 비활성화 |
| 실제 버전 충돌 | 최신 정보 재조회와 재시도 안내, 다른 탭 변경을 자동 덮어쓰지 않음. 기존 완료 사진은 유지 |
| 요청 결과 보관기간 만료 | 410 REQUEST_RESULT_EXPIRED이면 자동 재시도를 멈추고 결과 보관기간 만료를 표시한다. 기존 업무 목록 확인 동선을 제공한다. 새 키 실행 버튼을 복구 수단으로 제공하지 않는다. |

E2E-36~42를 화면과 API 양쪽에서 검증한다. 특히 승인 후 아무 조작을 하지 않았을 때 발송되지 않는지, 10장 사진을 선택해도 정상적으로 모두 연결되는지, 처리 응답이 끊겨도 같은 신청·첨부·메시지가 중복 생성되지 않는지 확인한다.

실패한 파일은 다시 시도하거나 선택 목록에서 제거할 수 있다. 제거한 미연결 파일은 제출 필수 사진 수에 포함하지 않으며 서버의 만료 정리 대상이다. 이미 연결된 첨부의 제거는 별도 detach 성공 후에만 화면에서 반영한다.
