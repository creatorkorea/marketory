# Auth UI Implementation Plan

**Goal:** 승인된 1~3번의 인증·요청 복구 화면을 실제 API 계약에 연결한다.
**Architecture:** Supabase browser SDK + allowlisted Next relay + Python 권한 검증. actor별 요청 키와 공통 복구 상태기계.
**Tech Stack:** 기존 Next/React/Pretendard, Supabase JS, Vitest, Playwright.
**Spec:** [설계](../specs/2026-10-09-auth-ui-design.md)
**Execution:** 현재 작업공간에서 직접 실행, 마지막 독립 검토 1회. 시작 시 Git 저장소가 없었으며 도중 사용자 요청으로 origin 연결 완료. 초기 커밋·push는 수행하지 않음.

- [x] 복구·relay 실패 테스트 작성 후 최소 구현, 같은 키·취소·권한·만료 검증.
- [x] OTP SDK adapter/로그인/계정 화면과 공통 상태 컴포넌트 구현.
- [x] 브라우저 성공·실패·재로그인·모바일 검증, 타입/빌드/API 회귀 확인.
- [x] 연결 가능한 외부 설정 확인, 운영 연결 안내와 검증 한계 기록.

검증: 웹 단위 21 + 브라우저 10 + API/실제 로컬 PostgreSQL 31 통과. 빌드·타입·문서·토큰·UI strict 검사 통과. 독립 검토 1건을 SDK 실제 동작과 대조해 로그아웃 장애 안내로 수정하고 브라우저 재검증했다. 외부 Supabase 프로젝트 생성/migration/OTP 수신은 미실행이며 [연결 안내](../../AUTH-SETUP.md)에 분리했다.

Review focus: 새로고침 중 응답 유실; 계정 전환 중 늦은 응답; 인증번호 오류와 재전송; 보관 만료 키 재사용; 외부 redirect/비밀 노출.

Ruling: 사용자 ‘진행’과 이미 승인한 v1.3/디자인/1~3 범위를 적용하여 구현까지 계속한다. 외부 조직 선택만 누락 정보로 질문하고 독립적인 로컬 작업은 진행한다.
