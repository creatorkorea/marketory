# 마켓 관리 구현 계획

사용자가 승인한 다음 작업 1~3번을 기존 v1.3 계약 안에서 진행한다. 신규 인증 흐름·새 디자인 방향은 만들지 않는다.

1. 실제 로그아웃 및 지정 관리자 이메일 인증을 확인한다. 최초 관리자는 명시 지정된 계정에만 DB 트랜잭션과 감사 기록으로 부여한다. 셀러 계정은 그대로 유지한다.
2. 인증 수정·SMTP 연결 증거와 오래된 상태 문서를 정리하고 검증 후 커밋·푸시한다.
3. projects의 기존 스키마를 이용해 생성(DRAFT), 상세, 설정 수정, 명시 상태 전환, 관리자 전용 멤버 배정을 구현한다. 생성은 플랫폼 관리자 또는 활성 배정 OPERATOR만 허용하고 생성자에게 OPERATOR를 부여한다. STAFF라는 이유만으로 생성 권한을 주지 않는다.
4. 모든 변경에 Idempotency-Key·expected_version(생성 제외)·사유·감사 기록을 적용한다. 정책 JSON은 schema_version=1 타입 검증, 심사 가중치 합100, KST 단일 행사일·모집/종료 기한을 검사한다. 공개에 동의 문구·버전·정책·부스조건이 필요하다. 시안 예시를 실제 운영값으로 채우지 않는다.
5. /markets 목록·새 마켓·설정 화면을 기존 토큰·Field/Button/Notice로 구현한다. 비로그인·무권한·빈 목록·오류·버전충돌·응답 유실 복구를 제공한다. 업무 입력은 화면 메모리에 유지하고 복구 키/본문은 새 키 자동 생성 없이 재사용한다. 첫 범위는 기본 마켓 설정이며 신청 건수는 아직 생성하지 않으므로 허위 집계를 표시하지 않는다.
6. 실제 PostgreSQL 테스트로 권한·중복 생성·정책 버전·상태/시각·권한 회수·경합을 검증하고, 웹 테스트·빌드·브라우저로 화면을 확인한다. 실제 행사는 사용자 운영값이 없으므로 임의 공개하지 않는다.

운영 경계: 최초 관리자 계정은 사용자가 별도로 지정한 이메일 계정. 인증이 끝나기 전 권한을 부여하지 않는다. SMTP 실수신은 완료했으며 기존 계정 재로그인·실제 세션 만료는 각각 확인한 범위만 기록한다. Vercel/Render 배포는 이번 작업에 포함하지 않는다.
