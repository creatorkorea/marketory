# P0 개발 기반 설계

사용자가 승인한 P0 범위와 Vercel·Render·Supabase 결정을 실행한다. 제품 업무 기능은 P1 이후이며 이번 범위는 재현 가능한 기반이다.

- Node 24 / npm workspaces, Python 3.12 / uv. 설치된 패치 버전과 의존성을 파일로 고정한다.
- Next.js App Router + TypeScript + Tailwind. 기존 DESIGN.md → tokens.css를 직접 import하고 Pretendard를 로컬 로딩한다. 홈은 준비 상태, /ui는 기본 버튼·입력의 로컬 견본으로 표시한다. 인증·신청 성공을 가장하지 않는다.
- FastAPI /health/live는 프로세스 생존, /health/ready는 실제 DB SELECT 성공 여부를 구분한다. DB 미설정/장애는 503이며 DSN·예외 원문을 응답에 넣지 않는다.
- psycopg의 명시적 transaction context를 DB 경계로 사용한다. SQL migration은 supabase/migrations에서 관리한다. P0에서 업무 테이블을 미리 만들지 않는다.
- worker는 별도 Python 진입점과 종료 신호 처리, DB 상태 확인을 가진다. P0는 생존 프로브이며 업무 queue 처리를 구현했다고 주장하지 않는다. claim·외부 작업은 P3/P5/P7.
- OpenAPI snapshot을 FastAPI에서 생성하고 openapi-typescript로 타입을 생성한다. CI는 드리프트를 검사한다.
- 같은 Docker 이미지에 API와 worker 명령을 제공한다. 로컬 compose에는 개발 PostgreSQL만 포함한다. 이는 Supabase Auth/Storage 대체가 아니다.
- 외부 계정 생성·유료 서비스 활성화·배포는 이번 로컬 구축에 포함하지 않는다.

검증: API 생존/DB 미설정/실패/성공, CORS, worker 종료·실패 복구, PostgreSQL 트랜잭션 commit/rollback, 타입 생성·타입검사·빌드, UI 모바일·키보드·폰트. 현재 PC Docker 부재는 실행 한계로 기록한다.
