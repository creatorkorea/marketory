# P1/P3 인증·권한·요청 복구 기반

사용자의 계속 진행 요청과 v1.3을 기준으로 구현한다. 제품 인증 UI·외부 OTP 발송은 제공사 연결 후 검증하며, 이번 산출물은 API와 실제 로컬 PostgreSQL 통합 검증이다.

- Supabase Auth /auth/v1/user에 bearer를 보내 서버 검증된 UUID·확인된 이메일만 신뢰한다. 사용자 metadata 역할은 무시한다. 미설정/제공사 장애는 503, 잘못된 인증은 401. HTTP 검증은 DB 트랜잭션 밖에서 수행한다.
- users(auth.users FK), projects, project_members, sellers, audit_logs, api_idempotency의 기반 migration. exposed public의 anon/authenticated 직접 CRUD는 차단하고 RLS를 활성화한다. 로컬 테스트의 auth.users 대용 테이블은 테스트 DB에만 만든다.
- POST /api/auth/bootstrap은 빈 입력과 UUID Idempotency-Key만 받는다. 신규 USER/SELLER/ACTIVE, 기존 역할 유지, 비활성 사용자 거절. 필수 프로필 없는 sellers 행을 임의 생성하지 않는다.
- GET /api/me, GET /api/projects 및 프로젝트 요약 조회. 서버 DB의 활성 사용자·STAFF·멤버 권한을 확인하고 프로젝트 미배정은404, 행위 부족은403. 프로젝트 생성·파일·출력은 후속 기능이다.
- 요청 core는 actor/operation/key별 DB transaction advisory lock과 UNIQUE를 사용한다. hash는 method·정규 경로·대상·본문을 포함. EXPIRED 먼저410, 현재 권한 검사 후 동일 hash 저장 응답 재생, 다른 hash409. 최초 처리에만 expected_version 검증(callback).
- IN_PROGRESS는 deferred constraint trigger로 커밋 금지. callback 업무·감사·결과는 한 트랜잭션, 업무 거절은 savepoint rollback 후 FAILED 저장, 기술 예외는 전체 rollback.
- 결과 조회는 현재 권한 재검사, 본인 행 없음202, EXPIRED410. 만료 함수는 완료·비동기 미확인 없음 조건을 확인하고 최소 행만 보존한다. 자동 만료 배치는 운영 보관기간 승인 전 비활성.
- 비동기 자원 유형은 아직 구현하지 않으므로 만료 허용 목록은 동기 users/projects만. 후속 작업 resource 종류는 보수적으로 만료 거절하여 UNKNOWN/QUEUED 오삭제 방지.

검증: 실제 Postgres migration·RLS·권한 회수·인증 위조/장애·동일/다른 키·동시 경합·커밋 전 중단·커밋 후 재시도·IN_PROGRESS DB 금지·FAILED·EXPIRED 및 타인 조회. 모든 업무 E2E를 통과했다고 표기하지 않는다.
