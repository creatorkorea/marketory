# 마켓 공통 안내 설계

상태: 사용자 검토용. 기능 범위는 승인되었으며, 이 문서의 상세 규칙 검토 후 구현 계획을 작성한다.

## 목적과 완료 기준

운영자가 입장 시간·준비물·주차 안내를 한 번 작성하고 해당 마켓의 대상 셀러들이 내 신청에서 확인하도록 한다. 사용자 승인 범위는 공통 안내 작성, 전체 신청자/참가 확정자 대상 선택, 개별 안내와 구분된 셀러 조회, 기존 초안→승인→게시 및 게시 내리기 규칙이다. 이메일 발송·예약 게시·읽음 추적·첨부파일은 이번 범위에 포함하지 않는다.

완료 기준은 운영자의 초안 저장·승인·게시·수정·재게시·내리기, 대상 상태에 맞는 셀러 조회, 마켓/계정 격리, 저장 응답 유실 복구, 모바일 표시를 테스트로 확인하는 것이다. 로컬 구현과 운영 DB 적용/배포/실계정 검증은 별도 완료 상태로 보고한다.

## 현행 구조와 접근 선택

현재 `communications`는 application_id, recipient_snapshot과 이메일 발송 상태가 필수이며, worker·발송 이력·신청 변경 트리거가 연결되어 있다. 공통 안내를 위해 이 제약을 완화하면 기존 발송 경로까지 영향을 받는다.

검토한 방식:

1. 셀러마다 기존 안내 복제: 기존 구조를 활용하지만 수정·게시 내리기 일관성과 신규 신청자 처리에 비용이 크다.
2. 기존 communications에 마켓 범위 추가: 한 관리 모델을 쓸 수 있지만 신청·수신처 필수 제약과 발송 worker를 함께 바꿔야 한다.
3. **추천: 별도 market_announcements 저장소와 작은 API/UI 모듈**. 기존 권한, 트랜잭션, 멱등 처리, 대화상자·게시본 표시 패턴을 재사용하고 기존 개별 안내 및 이메일 로직은 유지한다.

## 공개 대상 규칙 — 제안 기본값

대상은 조회 시점의 신청 상태로 판단한다. 운영자 화면에 이 규칙을 설명한다. 게시 당시 수신자 명단을 고정하거나 안내를 신청별로 복제하지 않는다.

| 값 | UI 명칭 | 조회 조건 |
| --- | --- | --- |
| ALL_APPLICANTS | 전체 신청자 | 제출 이력이 있고 현재 상태가 SUBMITTED, NEED_INFO, REVIEWING, APPROVED, WAITING, REJECTED, CONFIRMED 중 하나 |
| CONFIRMED | 참가 확정자 | 현재 상태가 CONFIRMED |

작성 기본값은 참가 확정자로 한다. 전체 신청자는 미선정자도 포함한다는 설명을 표시한다. 초안·취소·삭제 신청은 공통 안내를 볼 수 없다. 나중에 접수/참가 확정한 셀러도 대상 조건을 충족하면 기존 게시 공지를 볼 수 있다. 참가 취소 후에는 공통 안내를 볼 수 없으며, 기존 개별 안내의 이력 조회 동작은 그대로 유지한다.

초안의 대상 수정은 현재 게시 대상에 영향을 주지 않는다. 제목·본문·대상을 한 게시본으로 저장하고 명시적으로 재게시할 때 함께 교체한다. 행사 종료 후에도 대상 조건을 충족하는 본인의 신청에서 게시 이력을 조회할 수 있다. 삭제된 마켓은 조회를 차단한다.

## 데이터와 상태 전이

`public.market_announcements`에 announcement_id, project_id, subject(1–200자), body(1–50000자), audience, content_version, version, created_at, updated_at을 저장한다. 공백뿐인 제목·본문은 거부한다.

승인 정보는 approved_version/by/at, 게시본은 published_subject/body/audience/content_version/at/by, 게시 내림은 withdrawn_at으로 구분한다. 승인 정보는 모두 비어 있거나 현재 content_version과 일치해야 하며, 게시본 필드는 모두 비어 있거나 완전해야 한다. 게시된 내용 버전은 현재 내용 버전 이하여야 한다. FK와 대상 enum 제약을 DB에도 적용한다. 테이블은 RLS를 켜고 anon/authenticated의 직접 접근을 차단한다.

| 작업 | 조건·결과 |
| --- | --- |
| 작성 | 운영 권한·행사 종료 전. 내용 1판의 미승인 초안 생성 |
| 수정 | expected_version 일치. 내용 버전 증가·승인 초기화. 기존 게시본 유지 |
| 승인 | expected_version 및 content_version 일치. 현재 내용 버전 승인 |
| 게시/재게시 | 현재 내용 승인 필요. 예상 버전·내용 버전 확인 후 제목·본문·대상을 복사하고 withdrawn_at 해제 |
| 게시 내리기 | 현재 게시 중인 경우만 허용. withdrawn_at 기록, 저장된 본문 유지 |

동일한 내용 버전의 활성 게시본을 다시 게시하면 409를 반환한다. 내린 게시본은 승인된 현재 버전으로 다시 게시할 수 있다. 행사 종료 후 작성·수정·승인·게시는 차단하고 게시 내리기는 허용한다. 권한이 회수된 운영자는 이력 조회·작업 결과 복구를 포함한 접근이 차단된다.

모든 쓰기는 처리 사유(1–2000자), Idempotency-Key, 기존 execute 트랜잭션을 사용한다. 상태 변경과 감사 로그 기록은 원자적이다. 운영자 읽기 응답에 allowed_actions를 제공하되 실제 API에서 권한·상태·버전을 다시 검사한다. 잠금은 기존 마켓→리소스 순서를 따른다.

## API와 권한

- 운영자 목록/작성: `GET/POST /api/projects/{project_id}/announcements`.
- 운영자 상세: `GET /api/announcements/{announcement_id}`.
- 변경: `POST /api/announcements/{announcement_id}/revise|approve|publish|unpublish`.
- 셀러 조회: `GET /api/applications/{application_id}/market-notices`.
- 공통 쓰기 작업 이름은 `announcements.create|revise|approve|publish|unpublish`. 요청 결과 조회 허용 목록, authorize_result, 웹 relay, 클라이언트 저장 요청 복구 허용 목록까지 함께 연결한다. 생성 실패 결과도 해당 마켓의 운영 권한으로 재검사한다.

운영자는 해당 마켓의 OPERATOR 또는 PLATFORM_ADMIN만 허용한다. 다른 마켓 운영자·일반 셀러·권한 회수된 계정의 접근을 차단한다. 셀러 조회는 기존 require_application으로 활성 사용자·본인 신청·삭제 여부를 확인한 뒤 마켓과 공개 대상 조건을 서버에서 적용한다. anonymous는 401, 다른 사람 신청은 404이다. 본인 신청이 대상 조건을 충족하지 않으면 빈 목록을 반환한다.

셀러에게는 announcement_id, 게시 제목·본문·대상·내용 버전·게시 시각만 반환한다. 초안, 처리 사유, 작성자, 승인자, 이메일, 감사 로그는 반환하지 않는다. 비로그인 공개 마켓 상세에는 공지를 노출하지 않는다.

운영자 목록은 기본 20/최대 100개, 생성 시각 내림차순과 ID로 정렬한다. 셀러 목록은 기본 5/최대 20개, 게시 시각 내림차순과 ID로 정렬하며 limit+1 조회로 has_more를 계산한다. 마켓/게시 목록 인덱스를 각각 추가한다. 새로고침은 첫 페이지로 돌아가고, 게시 내리기로 현재 페이지가 비면 이전 페이지 이동을 제공한다. 인증 응답은 no-store를 유지한다.

## 화면

기존 셀러 안내 화면에 ‘마켓 공통 안내’와 ‘개별 안내’로 이동하는 명확한 링크를 둔다. 공통 안내는 `/markets/{id}/announcements`에서 목록과 편집 영역을 제공한다. 기존 Pretendard, 색상, 여백, 버튼, 확인 대화상자, 미저장 경고를 재사용한다.

작성 폼은 대상·제목·본문·처리 사유로 구성한다. 승인과 게시를 별도 버튼으로 제공하고 게시 확인 대화상자에 제목·내용 버전·대상과 조회 시점 상태 기준임을 표시한다. 이전 게시본과 아직 게시하지 않은 변경 내용을 구분한다. 저장 결과가 불확실하면 기존 요청 확인/재시도를 사용하며 중복 쓰기를 만들지 않는다. 동시 수정 409는 새 상태 확인 후 사용자 재검토를 요구한다.

셀러 내 신청 상세와 공개 신청 재진입 화면의 공통 컴포넌트에 ‘마켓 공통 안내’, ‘내 신청 개별 안내’를 구분한다. 두 영역은 독립적으로 로딩·실패·재시도·빈 상태·페이지를 관리하고 각 제목과 연결된 새로고침 이름을 사용한다. 본문은 HTML로 해석하지 않는 일반 텍스트이며 줄바꿈·긴 제목·긴 문자열이 320px 화면에서도 넘치지 않도록 한다. 새로고침 중에는 버튼을 잠근다.

## 검증과 배포

API 통합 테스트: 전체 상태별 공개 대상 표, 타 마켓·타 셀러·비활성 사용자 차단, 비운영자 쓰기 차단, 동시 수정 버전 충돌, 중복 요청 및 결과 복구, 대상 변경 전후 게시본 유지, 승인 후 별도 게시, 내림·복원, 행사 종료 경계, 페이지 정렬·빈 페이지, 직접 DB 접근 차단을 검증한다. 취소/권한 회수 후 재조회에서 이전 내용을 반환하지 않는지도 확인한다.

웹 테스트: 대상과 게시본 표시, 미저장 변경 방지, 성공·실패·지연·권한·빈 상태, 새로고침 복구, 공통/개별 목록 독립 동작, 긴 본문 일반 텍스트 렌더링을 검증한다. 기존 개별 안내/발송 worker 회귀 테스트를 함께 실행한다. OpenAPI와 타입을 갱신하고 타입 검사·lint·프로덕션 빌드를 수행한다.

배포는 새 테이블 migration→API→웹 순서다. 기존 구조를 수정하지 않는 추가 migration으로 구버전과 호환한다. 운영 검증은 기존 테스트 마켓에 테스트 공통 안내를 작성해 대상 선택→승인→게시→셀러 조회→내림→재게시를 확인한다. 이메일 발송은 수행하지 않는다. DB를 직접 수정해 신청 상태나 인증을 우회하지 않는다. 운영 적용과 실제 브라우저 검증 결과는 별도 증거로 기록한다.
